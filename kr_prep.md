# Подготовка к контрольной работе

## Когда выбрать rebase, а когда merge?

Rebase выбираю для своей локальной feature-ветки, когда хочу перенести её на
актуальный main и получить линейную историю до публикации. Merge выбираю для
уже опубликованных веток или когда важно сохранить факт параллельной разработки
и не переписывать историю.

## Что будет при rebase публичной ветки?

Rebase создаст новые хеши коммитов и изменит историю, которую уже скачали
коллеги. Их локальные ветки разойдутся с удалённой, появятся сложные конфликты,
а для исправления может потребоваться force push. Поэтому публичные ветки
ребейзить нельзя.

## Зачем нужен multi-remote?

Multi-remote позволяет синхронизировать проект с несколькими серверами:
например, GitHub использовать для командной работы, GitLab — как резервное
зеркало, а отдельный fork — для участия в Open Source. Это повышает надёжность
и позволяет работать с разными площадками.
